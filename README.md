# זמני מניינים (גרסה 3)

מערכת לניהול זמני מניינים בבתי כנסת: API על Cloudflare Workers + D1, וממשק ניהול בעברית.

## שני תפקידים בלבד

| תפקיד | מה הוא עושה |
|---|---|
| **מנהל מערכת** (`admin`) | יוצר בתי כנסת ומשתמשים, משייך מנהלים לבתי כנסת, קובע מה מותר לכל בית כנסת, ומנהל את הרשימות המשותפות (תפילות, זמני ייחוס, עונות, אזורים). יכול גם להיכנס לכל בית כנסת ולערוך אותו |
| **מנהל בית כנסת** (`manager`) | נכנס ורואה רק את בית הכנסת שלו (או את בתי הכנסת שלו). מנהל מניינים ומיקומים, ועורך את פרטי בית הכנסת אם המנהל הכללי אפשר זאת |

**מה המנהל הכללי קובע לכל בית כנסת:** מכסת מניינים, מכסת מיקומים, האם מותר לערוך את פרטי בית הכנסת, והאם להגביל את סוגי התפילות. מנהל בית הכנסת רואה את ההגדרות האלה בלשונית "פרטי בית הכנסת".

## מניין

- **תפילה:** מתוך הרשימה. למשל: שחרית או מנחה.
- **זמן קבוע** (`07:30`), או **זמן יחסי** (`15 דק׳ לפני שקיעה`). זמן קבוע נבדק מול טווח השעות שהוגדר לתפילה.
- **ימים:** אילו ימים בשבוע. נשמר כ-bitmask: ראשון = 1, ... שבת = 64, כל יום = 127.
- **מיקום:** אופציונלי.
- **עונה:** אופציונלית. ריק = כל השנה.
- **הערה:** מוצגת לציבור.
- **מוצג / מוסתר:** אפשר להסתיר מניין זמנית בלי למחוק אותו.

## מבנה

```
api/                     ה-API (Cloudflare Worker)
  src/index.js           ניתוב, אימות, CORS, שגיאות, ניקוי יומי
  src/auth.js            סיסמאות, סשנים, הגבלת ניסיונות, בדיקות גישה
  src/minyan.js          כללי מניין: ולידציה, תוויות, מיון
  src/routes/            auth · workspace (מנהל בית כנסת) · admin · public
  migrations/            סכימת D1
  test/                  בדיקות אינטגרציה (node:test, מסד בזיכרון)
admin/                   ממשק הניהול: קבצים סטטיים בלי שלב build (Preact + htm, בתוך vendor/)
  config.js              כתובת ה-API (ריק = אותו דומיין)
scripts/preview.mjs      הרצה מקומית בלי wrangler
docs/API.md              כל ה-endpoints
```

הממשק מדבר עם ה-API רק דרך HTTP, ולכן הוא נפרד לגמרי מהשרת. ראו "הפרדת ממשק הניהול" בהמשך.

## העלאה לאוויר

מסד הנתונים `zmanim` כבר קיים, הסכימה כבר הוחלה עליו, וה-id שלו כבר כתוב ב-`wrangler.toml`.

1. **סוד להתקנה הראשונית.** זה חד-פעמי, ומונע ממישהו אחר "לתפוס" את המערכת לפניכם:
   ```bash
   npx wrangler secret put SETUP_KEY
   ```
   או בדשבורד של ה-Worker: Settings ← Variables and Secrets ← Add ← Secret.
2. **פריסה:**
   ```bash
   npm install
   npm run deploy      # מריץ מיגרציות חדשות (אם יש) ואז wrangler deploy
   ```
3. **יצירת המנהל הראשון.** פותחים את כתובת ה-Worker בדפדפן. מופיע מסך "התקנה ראשונית": מזינים את ה-SETUP_KEY, שם, מייל וסיסמה. המסך הזה עובד רק כל עוד אין אף משתמש במערכת.
4. **בתוך המערכת:** יוצרים משתמשים מסוג "מנהל בית כנסת", יוצרים בתי כנסת, ומשייכים כל מנהל לבית הכנסת שלו.

## פיתוח

```bash
npm test                       # 20 בדיקות אינטגרציה, ללא רשת
node scripts/preview.mjs       # http://localhost:8787, מסד בזיכרון, מפתח התקנה: preview

```

## הפרדת ממשק הניהול

כרגע ה-Worker מגיש גם את ה-API (בנתיבים `/api/*`) וגם את התיקייה `admin/`. כדי להעביר את הממשק לפרויקט נפרד:

1. מעתיקים את `admin/` לפרויקט חדש. כל אחסון סטטי מתאים: Pages, Worker עם assets או Netlify.
2. ב-`admin/config.js` מגדירים את `apiBase` לכתובת ה-API.
3. ב-`wrangler.toml` של ה-API מוחקים את הבלוק `[assets]`, ואפשר גם להגדיר את `ALLOWED_ORIGINS` לדומיין של הממשק.

## אבטחה

- **סיסמאות:** מוצפנות ב-PBKDF2-SHA256 עם salt.
- **טוקנים:** נשמרים במסד רק כ-hash. תוקפם 30 יום, ולכל משתמש עד 10 מכשירים.
- **ניתוק:** החלפת סיסמה, איפוס סיסמה או השבתת משתמש מנתקים את כל הסשנים.
- **הגבלת ניסיונות כניסה:** נעילה אחרי 5 כשלונות לאותו מייל, או 30 כשלונות מאותה כתובת IP.
- **פרטיות:** מנהל בית כנסת שמנסה לגשת לבית כנסת שאינו שלו מקבל 404, כך שאי אפשר לגלות מזהים של בתי כנסת אחרים.
- **שאילתות:** כל השאילתות עם פרמטרים, ושמות טבלאות מגיעים רק מרשימה קבועה בקוד.
- **שגיאות:** שגיאות פנימיות לא נחשפות למשתמש. מוחזר רק קוד הפניה ללוג.
